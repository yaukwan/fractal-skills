# Decision Review Checklist

Use this before creating or accepting a decision doc.

- Does this describe current system-level truth rather than local task reasoning?
- Would future contributors be expected to follow this as an authority?
- Is the topic cross-cutting or durable enough to outlive the current task?
- Does an existing decision already cover this topic?
- If yes, should that existing doc be updated instead of creating a new one?
- Could this content belong in `engineering/` instead?
- Could this content stay in `research/` or thread context instead?
- After this change, will exactly one current authority be obvious for this topic?
- If an older decision becomes stale, is its status made explicit?
