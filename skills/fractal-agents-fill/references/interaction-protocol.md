# Blocking Interaction Protocol

Use this only when evidence cannot safely settle module ownership, a durable constraint, or domain language.

## Before asking

Check code, tests, the nearest manifests, relevant project skills, nearby docs, and settled conversation context. Observable facts should be resolved from the repository.

## Ask one blocking question

Ask one focused question with:

- the conflicting evidence
- the contract wording each answer would produce
- a recommended answer and reason

Useful forms:

> I read this directory as the long-term owner of **X**, while **Y** appears to be an integration edge. I recommend recording only **X** in Scope because the public entry point and current decision both place **Y** elsewhere. Is that current truth?

> The existing manifest preserves contract **A**, but the current decision requires **B**. I recommend blocking this manifest and recording a `decision_drift_signal` until authority is resolved. Agreed?

> Code uses **account** for two objects, while the current decision defines this module's term as **customer account**. I recommend the precise term and excluding the ambiguous synonym. Is that intended language?

The user may answer `skip` to leave the claim unwritten or `done` to stop questioning and report the module as blocked. Do not continue detail questions after the direction is safe.
